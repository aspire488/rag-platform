**Date:** 2026-10-19

## 1. Motivation

Two owner-driven facts make the local-first *generation* path the wrong default for this machine, while leaving the local-first *retrieval* core untouched:

1. **Resource safety (overriding principle).** The owner's binding requirement is that system resource safety outranks all features and benchmarks: a useful, measurable RAG engine that runs comfortably on this 15 GB laptop — not maximum features. Incident evidence recorded in `docs\RESOURCE_BUDGET.md` §5.5 (2026-10-19; classified there as incident evidence, **not** valid BG-1a results — no throughput data) showed an 8B-class local model driving host RAM to an emergency abort (RAM floor observed at 148 MB) with the start gate repeatedly failing at idle. Cloud inference, when explicitly enabled, removes that local RAM pressure entirely.
2. **Architecture request.** The owner directed this revision: cloud-first generation (Groq → Gemini → OpenRouter as candidates) with Ollama retained only as a guarded, resource-gated local fallback, while ingestion, chunking, keyword/vector search, ranking, authorization, evidence assembly, citation mapping, evaluation, and observability stay local and fully functional when every LLM provider is unavailable.

Crucially, "cloud-first" is documented as the **configured failover order**, not the default state: egress stays off, no provider is configured or authenticated, retrieval-only remains the default mode, and every existing resource gate, threshold, and approval gate remains binding (§2 Z3/Z4/Z10/Z14).

## 4. Implications

- **Privacy/egress:** egress remains off by default; enabling a provider is explicit owner action + I4 allowlist; only minimum post-verified evidence may be transmitted (I16); authorization always precedes prompt assembly; provider retention/training-use terms must be verified — no privacy guarantees beyond our own boundaries are claimed; a future document-level no-external-processing flag is documented.
- **Cost:** free tiers only; no billing/purchase/upgrade code path may exist (I15/Z13); payment-required = permanent skip; attempt caps prevent runaway loops; no key is required for any gate (Z2).
- **Reliability:** deterministic sequential failover with bounded timeouts/retries and a per-query attempt cap; clean skip of unconfigured/permanently-failed providers; retrieval-only continuity always available; honest failure categories recorded; exactly one user-visible result.
- **Resource safety:** unchanged thresholds (3 GB start gate, 2 GB emergency floor, no automatic lowering) plus the newly recorded 90 %-total-RAM operational ceiling with its user-space honesty caveat (§10.4); cloud generation relaxes nothing locally; no gate is ever traded for responsiveness (Z14).

## 5. Risks and mitigations (summary)

New risks R23–R29 (over-broad prompt transmission, free-tier drift via activated R10, credential leakage, cost runaway, provider behavioral drift, egress-bypass defect, provider latency/availability variance) with mitigations in the §13 table: I14–I16, §5.1 caps/taxonomy, §5.2 content rules, §9.6 structural tests, socket instrumentation in every gate run, dated provider verification, and per-provider metric separation so provider drift can never mask a retrieval regression. Existing risks R1–R22 otherwise carry unchanged.
